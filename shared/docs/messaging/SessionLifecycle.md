# Session Lifecycle

## Creation
The `SessionManager` receives an initial `DoubleRatchetState` (generated by the Handshake engine). It wraps it in a `SecureSession` and stores it in memory.

## Active State
As the business logic sends and receives messages, the `SecureSession` internally mutates the `DoubleRatchetState` (advancing message numbers, deriving keys). 

## Closure / Expiration
If a session is inactive for an extended period, or if the user logs out, the `SessionManager.remove_session()` method is invoked. This calls `destroy()` on the `SecureSession`, which forces a garbage-collection sweep of the internal crypto state.
